# 报告内容合同（唯一语义源）

本文件定义报告 coder 必须写进模板和 renderer 的读者合同。`SKILL.md` 定义执行顺序；本文件定义
成稿必须呈现什么。规则只停留在本文件、没有对应模板锚点/样式/renderer 逻辑，不算实现。

目录：[角色与事实](#1-角色模式与事实边界) · [读者与证据](#2-gate-1读者与证据目标) · [章节](#3-固定章节与可见顺序) · [分析点](#4-分析点与结论边界) · [表格](#5-结果表公开输出表与版本表) · [图件与 Note](#6-figure图注与语义-note) · [语言](#7-语言术语与结论强度) · [验收](#8-状态门禁与-receipt)

## 1. 角色、模式与事实边界

报告 coder 在开发期完成固定 prose、图题图注、表格定义、模板版式和 R/Python renderer；运行期只做
事实校验、slot 填充和渲染。正式报告不调用 AI 改写，不重算统计，不临时重画图，不从文件名、日志、
配置、cache 或图片外观推断数字和语义。

科学算法、统计正确性和实际绘图逻辑由 source review/code coder 先确认；report coder 只核对其公开
provenance 与报告映射。代码、provenance、结果或图件互相冲突时停止并返回 `BLOCKED`，不在报告中另画或
替换一套“参考图”。

`module_reusable` 与 `one_off` 使用同一章节、slots、图表、Note、语言和验收合同。新模块默认
`report_templates/report_template.docx` + `scripts/report/generate_report.R|py`；存量 QMD/Rmd 模块在迁移
完成前可继续用原 renderer，但一项交付只能有一个生效模板，不能把 legacy 当成第二套规则。

## 2. Gate 1：读者与证据目标

在写模板前先查看实际源码、结果和已有研究索引；需要外部方法/术语资料时，将 URL/DOI、访问日期、采用
结论和冲突处理写入模块批准的 `docs/research/`（或等价长期文档），不把临时参考目录当运行依赖。这里的 URL
是科学来源记录，不是报告正文中的运行链接。随后冻结以下字段：

| 字段 | 要求 |
|---|---|
| `audience` | 一个主要领域读者群体及其决策场景，不写“所有人” |
| `terminology_sources` | 实际采用的术语来源，使用稳定路径、URL、DOI 或批准记录 |
| `evidence_targets` | 用陈述式标题表达报告要交付的事实目标，并关联 `analysis_point_ids` |
| `references` | 正文实际引用并支撑本次方法/解释的来源，内部记录名称、版本和来源地址；可见文案只显示名称/版本/用途 |

旧 `reader_questions` 只作为迁移输入，必须转换为陈述式 target；问号和任务句不进入标题、章节、图题、
图注、摘要或结论。每个 target 必须映射到一个或多个公开表/图、数字证据和来源；无法映射即
`EVIDENCE_NEEDED`，不从示例正文、字段名、函数名或软件介绍补写。

## 3. 固定章节与可见顺序

模板按下表保留语义；相邻章节可以合并显示，但不能丢失内容或生成空章节。

| 顺序 | 章节 | 必须呈现 | 事实来源 |
|---:|---|---|---|
| 1 | 标题与摘要 | 分析类型、对象/比较、目的和结果范围 | 项目信息、输入身份、已确认事实 |
| 2 | 数据范围与分析边界 | 纳入对象、推断单位、分组、比较方向和适用范围 | 输入/QC/provenance |
| 3 | 材料与方法 | 输入、核心方法及实际版本/引用、参数、效应量/统计量、校正与阈值 | calculation provenance、来源记录 |
| 4 | 质控与异常（适用时） | 可核对 QC、异常及其对解释的影响 | 结构化 QC、输入统计 |
| 5 | 结果与解读 | 每个 target 的固定结果段、表图和限制 | 公开结果表/图及 provenance |
| 6 | 综合结论 | 只回收正文已有事实，结论强度不超过证据等级 | 结果段、限制 |
| 7 | 局限、未完成与待验证 | 本次具体限制、受影响结论、仍成立范围和下一步用途 | design/method/evidence |
| 8 | 公开输出 | 实际业务文件名、内容、用途和消费者 | 当前发布树、合同 |
| 9 | 参考文献 | 正文实际使用的术语、方法、数据库/资源来源 | `references` |
| 10 | 软件与资源版本 | 实际软件/资源、版本、用途和来源 | calculate/plot/report provenance |

没有事实的可选章节整节省略；合同明确要求保留时才写有事实依据的 `N/A`。最后一个可见内容块是
紧凑版本表，不在其后追加工程说明。

## 4. 分析点与结论边界

每个分析点按此顺序组织固定 prose 和动态 slot：

```text
对象与范围 → 方法/版本/参数 → 推断单位与比较方向 → 结果数字/统计量
→ Figure/Table/真实文件 → 领域解释 → 限制/阴性状态/下一步用途
```

结果段对读者呈现为“结论 → 数字证据 → 领域解释 → 限制”。所有可见数字、阈值、比较方向、单位和
结论回溯到同一公开产物及其 provenance。有向比较写明
`metric = target − reference` 和正负方向；多重检验写明 adjustment 方法、family 与实际判定表达式。

`valid_no_findings` 是成功状态，使用“在本次数据和当前判定口径下未检出符合条件的结果”，不推测原因；
下游需要连续 schema 的结果表保留表头空表，不适用图/章节整项省略，不生成假图、假行或候选。

正文只保留研究问题、对象、范围、方法、结果、限制和公开文件。run ID、hash、cache、日志、调试、
审核状态、权限、治理和报告自身属于 `run_record.json` 或外部 receipt，不进入读者正文。

## 5. 结果表、公开输出表与版本表

- `result_table`：固定列名、顺序、显示名、单位、精度和脚注；只保留回答 target 所需的最小列/行。长表
  可固定展示前 10 行并指向完整业务文件。文本列左对齐，数值列右对齐，表头跨页重复，单条数据行不拆页。
- `output_table`：每个公开业务文件一行，至少有 basename/path、内容、用途和消费者；报告、日志、cache、
  hash、run record、QA 和模板不列入。一个逻辑图的多格式在正文合并为 `name.png(pdf)`，磁盘合同仍逐文件
  验证。禁止创建没有消费者的 filtered/top/gene-list 副本。
- `version_table`：列出实际使用的软件、数据库/参考资源、版本、用途和来源；不写 `NA`、内部路径、运行
  状态或色值代码，且必须是最后一个可见内容块。

## 6. Figure、图注与语义 Note

每个业务图固定为：

```text
连续编号的陈述式图题 → 一张完整真实源图 → 紧邻、自足、编号图注 → 正文解释
```

图注至少说明对象、比较/分组、panel、坐标轴与单位/变换、颜色/形状/线型、n 或统计层级、阈值和阅读
边界；语义来自 plot provenance，不从外观猜颜色。源图完整等比嵌入，禁止裁剪、分幅、续图和拉伸；
显示宽高比与源图误差不超过 0.1%。宽图通过源端画布或页面布局解决。PNG/PDF 都是实际发布文件，报告
不截屏、重画或把 PDF 拆成图片。

只有方向、单位/变换或解释边界可能造成关键误读时才插入 `notes[]`。Note 必须紧邻首次相关正文或图，
有可见 `Note` 标签和独立框体；去掉颜色仍能读懂。默认样式固定为：边框 `#5B9BD5`、填充 `#DDEBF7`、
标签 `#2F75B5`。黄色/棕色不是该语义 Note 的替代色；色值只存在样式，不写入客户正文。

## 7. 语言、术语与结论强度

标题、正文、表头、图题、图注、摘要、结论和 Note 使用自然、简洁的中文；图内标题、坐标轴、图例和标注
使用英文。软件/资源名、基因/蛋白符号、文件名和通用缩写保留原文，并在首次影响理解时解释。

可见标题和正文使用陈述句，不写问句、任务句、模板 marker 或营销文案。结论强度遵循
`interpretation_level`：`descriptive`（观察/分布）、`association`（相关/伴随）、`prediction`（模型提示）、
`candidate`（候选/待验证）、`mechanistic_hint`（机制线索）。只有设计和验证充分时才使用证明、因果、疗效、
安全性或临床价值等强措辞；摘要/综合结论不能引入正文没有的数字或方向。

默认视觉基准为中文宋体、英文和数字 Times New Roman、正文约 12 pt；主标题居中黑体约 22 pt，H1/H2/H3
约 16/14/12 pt，主标题色 `#0F4761`。字体回退必须没有缺字、方框、孤立标题或不可读表格。

## 8. 状态、门禁与 receipt

`draft` 允许继续填 slot，但只能输出 `DRAFT`/`EVIDENCE_NEEDED`；`release` 只有结构、视觉、证据三门
全部通过才可写 `PASS`。任一门失败为 `BLOCKED`，修复诊断 subject 后重跑。

验收必须完成：

1. 提取最终 DOCX 可见文本，将每个 target 映射到结论、数字证据、领域解释、Figure/Table 和来源；
2. 抽查全部数字、方向、阈值、引用、文件名、单位、版本和警告的一致性；
3. 核对媒体顺序、图题/整图/图注邻接、图注字段、表头分页、Note 触发与三色样式、源/显示宽高比；
4. 用目标阅读器逐页检查截断、溢出、tofu、空白页、孤立标题/图注、表格可读性和图片拉伸；
5. 逐个打开 standalone PNG/PDF，并记录实际 renderer、尺寸、DPI、字体 fallback；
6. receipt 记录模式、命令、输入/输出相对路径、模板/renderer 版本、三门结果、reviewer、时间和逐文件
   视觉结论；工程追溯留在 `run_record.json`，逐文件视觉证据留在 owning `testNN/visual-review.json`。
