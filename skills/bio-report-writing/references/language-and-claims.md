# 语言、术语与结论强度

模板固定句式，renderer 只插入已确认动态 slot；运行期不让模型重写段落。正文目标是让主要领域读者
从事实、数字、图表和限制得到可复核的解释，不是复述脚本或内部状态。

## 可见语言

- 标题、摘要、正文、表头、图题、图注、Note 和结论使用自然、简洁的中文；图内标题、坐标轴、图例和标注
  使用英文。
- 软件/资源名、基因/蛋白符号、文件名和通用缩写保留原文；首次影响理解时给出简短中文释义。
- 所有可见标题和段落使用陈述句，不写问号、任务句、模板 marker、占位符或营销文案。内部
  `evidence_targets` 也使用陈述式标题；历史 `reader_questions` 只在迁移记录中出现。
- 数字、单位、精度、方向、图表编号、方法名、版本、引用和文件扩展名在摘要、正文、表格、图注和发布树
  中保持一致；摘要和综合结论只能回收正文已有事实。

## 固定结果段

每个分析点先写限定范围的结论，再紧接可复核数字/统计量和相邻 Figure/Table，最后写领域解释与限制：

```text
结论 → 数字证据 → 领域解释 → 限制/下一步
```

解释必须注明推断单位、比较方向、阈值和适用边界。存在有向比较时写出
`metric = target − reference`；多重检验说明 adjustment 方法、检验 family 和实际判定表达式。
合法无发现使用固定表述“在本次数据和当前判定口径下未检出符合条件的结果”，保持成功状态，不推测原因。

## 结论层级

结论措辞不超过 `interpretation_level`：

| level | 允许的事实词 |
|---|---|
| `descriptive` | 观察到、包括、分布为 |
| `association` | 与……相关、在本数据中伴随 |
| `prediction` | 模型提示、在验证集表现为 |
| `candidate` | 优先候选、值得后续验证 |
| `mechanistic_hint` | 与……机制一致、提供机制线索 |

只有相应设计、对照和验证充分时才使用证明、验证、因果、疗效、安全性、临床价值、无混杂或稳定结合等
强措辞。需要表达边界时直接写“不能证明因果”等限定，并保留正确证据等级。

## 术语和事实来源

优先采用用户批准的术语表、Module Spec、原始论文/官方资源和目标领域交付。术语源冲突时在内部记录
选择依据；没有权威支持的术语、机制或翻译保持 `EVIDENCE_NEEDED`。不要从 DEGs 示例正文、字段名、函数名、
软件包宣传页或图像外观推导新模块内容。

## 默认版式

正文、表格和图注中文宋体，英文与数字 Times New Roman，正文约 12 pt；主标题居中黑体约 22 pt，H1/H2/H3
约 16/14/12 pt，主标题色 `#0F4761`。字体回退必须没有缺字、方框、孤立标题或不可读表格。Note 的天蓝
样式只属于提示框边框/填充/标签，不将色值代码写入客户正文。
